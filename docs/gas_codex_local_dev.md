# Codex CLIとclaspでGASをローカル開発しよう【完全初心者向け】

## この記事でできること

この記事を読み終えると、次のことができるようになります。

- PCのターミナルでコマンドを打てるようになる
- Node.js・claspをインストールして、ローカル環境でGASを開発できる
- GitHubにアカウントを作り、コードをバージョン管理できる
- AGENTS.md に仕様を書くだけで、Codex CLIがコードを自動生成してくれる
- 生成されたコードをclaspでGASに反映して、実際に動かせる

「GASって何？」「ターミナルを初めて開く」というレベルから書いています。
コマンドは1行ずつ、やっていることの説明も添えていますので、ゆっくり進めてください。

## 第2章　Node.jsをインストールする（nvm経由）

clasp・Codex CLI を使うためにまず「Node.js」が必要です。
Node.jsはプログラムを動かすための土台のようなものです。

ここでは **nvm（Node Version Manager）** を使ってインストールします。
nvm を使うと、Node.js のバージョンを簡単に切り替えられるため、開発環境として長く使えます。

### nvm をインストールする

**Macの場合：**

ターミナルで以下を打ちます：

```
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.39.7/install.sh | bash
```

インストール後、ターミナルを**一度閉じて開き直して**から以下を打って確認します：

```
nvm --version
```

`0.39.x` のようなバージョンが表示されれば成功です。

**Windowsの場合：**

nvm-windows を使います。
https://github.com/coreybutler/nvm-windows/releases を開き、
最新の `nvm-setup.exe` をダウンロードして実行してください。

インストール後、PowerShell を**一度閉じて開き直して**から以下を打って確認します：

```
nvm version
```

バージョンが表示されれば成功です。

### nvm で Node.js をインストールする

```
nvm install --lts
```

`--lts` は「安定版（推奨版）をインストールする」という意味です。

インストールが終わったら、使うバージョンを指定します：

```
nvm use --lts
```

### インストールできたか確認する

```
node -v
```

`v20.x.x` のようにバージョンが表示されれば成功です。

```
npm -v
```

`10.x.x` のようなバージョンが表示されれば、セットで入っているnpmも使えます。

> 🔍 npmとは：Node.jsと一緒にインストールされるツール管理の仕組みです。
> clasp も Codex CLI も npm を使ってインストールします。

> ✅ nvm を使うメリット：将来「このプロジェクトは Node.js 18、あのプロジェクトは 20」
> という場面が来たとき、`nvm use 18` のように切り替えられます。

## 第6章　GitHubを開設してリポジトリを作る

「コードの保存場所」と思ってください。

1. https://github.com を開く

### フォルダの中に入る

## 第7章　git の基本操作を覚える

これだけ知っていれば今回は大丈夫、という3つのコマンドです。

| コマンド | 意味 |
|---------|------|
| `git add .` | 変更したファイルを全部「保存の準備」にする |
| `git commit -m "メモ"` | 変更を記録する（メモ付き） |
| `git push` | GitHubに反映する |

まとめてセットで打つと覚えやすいです：

```
git add .
git commit -m "最初のコミット"
git push
```

> ✅ ポイント：ファイルを変更したら「add → commit → push」の流れで保存します。

### なぜ Codex を使う前にコミットするのか（セーブポイントの考え方）

今回は Codex CLI がコードを自動で書き換えます。
とても便利な反面、「意図しない変更をされてしまった」「前の状態に戻したい」という場面も起こります。

そのために、**Codex を動かす前に必ずコミットしておく**習慣をつけましょう。
コミットはゲームのセーブポイントと同じです。何かあっても、直前のセーブに戻れます。

```
git add .
git commit -m "chore: Codex実行前のセーブポイント"
```

戻したいときは以下のコマンドで1つ前のコミットの状態に復元できます：

```
git restore .
```

> ✅ 「とりあえずコミット → Codex 実行」の流れを習慣にしましょう。

### コンベンショナルコミットについて

今回は **Conventional Commits（コンベンショナルコミット）** という形式でコミットメッセージを書きます。
これはコミットの種類をメッセージの先頭に明記するルールで、変更履歴が一目でわかりやすくなります。

よく使う種類はこちらです：

| プレフィックス | 意味 | 例 |
|---------|------|-----|
| `feat:` | 新しい機能の追加 | `feat: Gmail一覧化機能を追加` |
| `fix:` | バグの修正 | `fix: 0件のときにエラーになる問題を修正` |
| `chore:` | ビルドや設定など雑務的な変更 | `chore: AGENTS.mdを追加` |
| `docs:` | ドキュメントの変更 | `docs: READMEを更新` |
| `refactor:` | 動作を変えないコードの整理 | `refactor: CONFIG定数を整理` |

Codex が自動でコミットするときも、この形式で記録するよう AGENTS.md に指示します。

## 第8章　claspでGASプロジェクトを作る

### claspでGoogleアカウントにログインする

```
clasp login
```

ブラウザが開いてGoogleアカウントの認証画面が表示されます。
許可すると、ターミナルに「Logged in!」と表示されれば成功です。

### スプレッドシートを用意する

ブラウザで新しいGoogleスプレッドシートを開きます（https://sheets.google.com）。
適当な名前をつけておきましょう（例：「GASハンズオン」）。

### claspでプロジェクトを作成する

`gas-hands-on` フォルダの中にいる状態で以下を打ちます：

```
clasp create --type sheets --title "GmailToSheet"
```

「スプレッドシートを選択しますか？」と聞かれたら、先ほど作ったスプレッドシートを選びます。

成功すると `.clasp.json` というファイルが作られます。
これがGASプロジェクトとの紐付け情報です。

### VS Codeでフォルダを開く

```
code .
```

（末尾の `.` は「今いるフォルダを開く」という意味）

VS Codeが開き、フォルダの中身が表示されます。

> 🔍 `.js` と `.gs` の違いについて：
> clasp を使うと、ローカル（VS Code）では **`.js`** ファイルとして扱われます。
> `clasp push` するとGASのサーバー上では **`.gs`** として認識されます。
> `clasp pull` でサーバーからコードを取得するときも、ローカルには `.js` で降りてきます。
> 「ローカルは `.js`、サーバーは `.gs`」と覚えておけば大丈夫です。

## 第9章　AGENTS.md を書いて Codex CLI にコードを作ってもらう

いよいよ核心です。
Codex CLI は、フォルダの中に置かれた `AGENTS.md` というファイルを「指示書」として読み込み、
その内容をもとにコードを自動生成します。
自分でコードを書く必要はありません。**作りたいものを日本語で書くだけ**です。

### AGENTS.md を作る

VS Codeで `gas-hands-on` フォルダの中に `AGENTS.md` という新しいファイルを作成し、
以下の内容をそのまま貼り付けて保存してください。

```markdown
# プロジェクト概要

このプロジェクトは Google Apps Script（GAS）を使って、
Gmail のメール情報を Google スプレッドシートに自動で一覧化するツールです。
clasp を使ってローカルで開発し、GAS のサーバーに push して動かします。

# 作成するファイル

## Code.js

以下の仕様で GAS のコードを作成してください。

### 機能仕様

- Gmail を検索して、条件に一致するメールを取得する
- 取得したメール情報を Google スプレッドシートに一覧化して書き出す

### 詳細仕様

- 検索条件: 直近7日以内のメール（newer_than:7d）
- 取得件数: 最大 10 件
- 出力先シート名: gmail_list（存在しなければ自動作成する）
- 実行のたびにシートをクリアしてから書き出す
- ヘッダー行（1行目）を固定する
- 検索結果が 0 件のときはエラーで止まらず、シートにメッセージを書く

### 出力する列（この順番で）

1. 受信日時（形式: yyyy-MM-dd HH:mm）
2. 件名
3. 送信者
4. 本文の先頭 80 文字
5. スレッド URL

### メニュー

スプレッドシートを開いたときに「GASハンズオン」というカスタムメニューを追加し、
そこから「Gmail一覧を作成」を実行できるようにする。

### コードの書き方

- 初心者向けにシンプルな書き方にする
- コメントは日本語でつける
- 設定値（検索条件・取得件数・シート名）は冒頭の CONFIG オブジェクトにまとめる

# 作業後の git コミット

コードの作成・修正が完了したら、必ず以下の手順で git コミットを行ってください。

1. 変更ファイルをステージングする
   ```
   git add .
   ```

2. Conventional Commits 形式でコミットする
   - 新機能追加のとき: `feat: （変更内容を日本語で簡潔に）`
   - バグ修正のとき: `fix: （修正内容を日本語で簡潔に）`
   - 設定・雑務変更のとき: `chore: （内容を日本語で簡潔に）`
   - リファクタリングのとき: `refactor: （内容を日本語で簡潔に）`

   例:
   ```
   git commit -m "feat: Gmail一覧化GASを作成"
   git commit -m "feat: 送信者メールアドレス抽出列を追加"
   git commit -m "fix: 検索結果0件のときエラーになる問題を修正"
   ```

3. GitHub への push は行わない（push はユーザーが手動で実施する）
```

## うまくいかないときのチェックリスト

### `node -v` でコマンドが見つからない

→ Node.jsを再インストールして、ターミナルを再起動してみる。

### `codex` コマンドが見つからない

→ `npm install -g @openai/codex` を再実行して、ターミナルを再起動してみる。

### `codex` 実行時に認証エラーが出る

→ `codex login` を再実行して、ChatGPT アカウントでサインインし直す。

### `clasp login` でブラウザが開かない

→ `clasp login --no-localhost` で試してみる。

### `clasp push` してもスプレッドシートに変化がない

→ スプレッドシートを再読み込みして、「GASハンズオン」メニューから再実行する。

### Gmail一覧が空っぽで出る

→ 検索条件が厳しすぎる可能性があります。AGENTS.md の検索条件を `newer_than:30d` に変更して `codex` を再実行してみる。

### 権限エラーが出る

## まとめ

今回やったことを振り返ります。

1. Node.js・clasp・Codex CLI をインストールして、ローカル開発環境を整えた
2. GitHubにリポジトリを作り、git でコードをバージョン管理した
3. clasp でスプレッドシートと紐づけた GAS プロジェクトを作成した
4. **AGENTS.md に仕様を書いて `codex` コマンドを実行するだけで、Code.js が自動生成された**
5. AGENTS.md に追記して再実行するだけで、仕様変更もコードを触らずに反映できた

自分でコードを書かなくても、「何を作りたいか」を日本語で書けばAIが作ってくれる時代です。
AGENTS.md はその「指示書」です。書き方が上手くなるほど、作れるものの幅が広がります。
